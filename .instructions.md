### Merging Rules
- **Always** use squash merge for PRs
- **No** force push on main/develop
- **No** direct commits to main/develop
- **Always** create a PR before merging
- PR requires 1 approval minimum
- CI must pass before merge

## Architecture Constraints

### Backend
Located in Backend/src/ with layered architecture:
- Api/ - Controllers, middleware, HTTP config
- Application/ - Contracts, DTOs, service interfaces
- Domain/ - Business entities
- Infrastructure/ - EF Core, SQL Server, external integrations

**Preserve:** JWT auth, Mercado Pago payments, provider API keys, IA integrations

### Frontend
Located in FrontEnd/src/app/:
- Angular 21 with protected routes
- Auth, payment, and admin guards
- Dashboard, discovery, resume, interview features

**Preserve:** Existing route structure and guard logic

### External
In external/ directory:
- MCP servers (LinkedIn, JobSpy, Apinfo, etc.)
- Each project evolves independently
- Document integration points clearly

## Development Workflow

1. **Read first:** Always consult AGENTS.md and existing docs
2. **Branch:** Create feature/bugfix branch with correct naming
3. **Code:** Keep changes atomic and well-scoped
4. **Commit:** Use Conventional Commits with emoji
5. **PR:** Create PR, wait for CI, request review
6. **Merge:** Use squash merge only

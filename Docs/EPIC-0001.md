# EPIC-0001 — Authentication Foundation and Angular Shell

## Objetivo

Implementar uma primeira versão funcional da aplicação com:

* Frontend Angular usando template Datta Able.
* Login com Google.
* Backend emitindo JWT próprio.
* Refresh token funcional.
* Tokens armazenados no frontend em `localStorage`.
* Área protegida autenticada.
* Isolamento de dados por `UserId`.
* Sem multi-tenant nesta fase.

O foco desta entrega é **funcionar corretamente antes de impressionar visualmente**.

---

## Regra principal

Não implementar funcionalidades fora do escopo deste épico.

Não criar:

* Multi-tenant.
* Organização.
* Workspace.
* Sistema de permissões complexo.
* MCPs.
* Chat IA.
* Leads.
* Dashboard avançado.
* Integrações extras.
* Tema visual customizado além do necessário.

Esta etapa deve provar apenas:

1. Usuário entra com Google.
2. Backend valida.
3. Backend cria ou atualiza usuário.
4. Backend retorna access token e refresh token.
5. Angular salva tokens.
6. Angular acessa rota protegida.
7. API responde `/api/me`.

```http
POST /api/auth/logout

```

Armazenar no `localStorage`:

```text

```

Não implementar cookie HttpOnly agora.

---

### 3. Sem multi-tenant

Não criar `Tenant`, `TenantId`, `Organization`, `Workspace` ou similares.

O isolamento da V1 será por:

```text
UserId
```

---

### 4. Login Google

Fluxo obrigatório:

```text
Angular recebe credential do Google
Angular envia credential para backend
Backend valida token Google
Backend cria/atualiza User
Backend emite JWT interno
Backend emite refresh token
Angular salva tokens
Angular redireciona para dashboard
```

## Entidades mínimas

### User

```text
Id
Name
Email
GoogleId
PictureUrl
CreatedAt
UpdatedAt
LastLoginAt
IsActive
```

Regras:

* `Email` deve ser único.
* `GoogleId` deve ser único quando existir.
* Usuário novo deve ser criado no primeiro login.
* Usuário existente deve ter `LastLoginAt` atualizado.

---

### RefreshToken

```text
Id
UserId
TokenHash
CreatedAt
ExpiresAt
RevokedAt
ReplacedByTokenHash
IpAddress
UserAgent
```

Regras:

* Refresh token deve ser salvo como hash.
* Refresh token deve ser rotacionado.
* Logout deve revogar o refresh token.
* Refresh token expirado ou revogado deve ser recusado.
* Reuso de token antigo deve ser tratado como inválido.

---

## JWT interno

Claims mínimas:

```text
sub = UserId
email
name
picture
```

O endpoint `/api/me` deve buscar os dados do usuário autenticado pelo `UserId` do token.

Não retornar dados falsos, mockados ou lidos diretamente do frontend.

## Backend — critérios de aceite

### `/health`

Deve retornar sucesso simples para confirmar que a API está no ar.

---

### `POST /api/auth/google`

Entrada:

```json
{
  "credential": "google_token_here"
}
```

Saída esperada:

```json
{
  "accessToken": "...",
  "refreshToken": "...",
  "expiresIn": 900
}
```

Critérios:

* Token Google inválido retorna `401`.
* Token Google válido cria usuário se necessário.
* Token Google válido autentica usuário existente.
* Retorna access token e refresh token.

---

### `POST /api/auth/refresh`

Entrada:

```json
{
  "refreshToken": "..."
}
```

Saída:

```json
{
  "accessToken": "...",
  "refreshToken": "...",
  "expiresIn": 900
}
```

Critérios:

* Refresh válido gera novo access token.
* Refresh válido gera novo refresh token.
* Refresh antigo é revogado.
* Refresh inválido retorna `401`.

---

### `POST /api/auth/logout`

Entrada:

```json
{
  "refreshToken": "..."
}
```

Critérios:

* Revoga o refresh token.
* Retorna sucesso mesmo que a sessão já esteja inválida, desde que não cause erro interno.

---

### `GET /api/me`

Critérios:

* Sem token retorna `401`.
* Token válido retorna dados do usuário.
* Token expirado retorna `401`.

---

## Frontend — critérios de aceite

### `/login`

Deve conter:

* Layout simples usando Datta Able.
* Botão de login Google.
* Tratamento básico de erro.
* Redirecionamento para `/dashboard` após login.

---

### `/dashboard`

Deve:

* Ser protegido por `AuthGuard`.
* Chamar `/api/me`.
* Exibir:

  * Nome
  * Email
  * Foto

Os dados devem vir da API.

---

### AuthService

Responsável por:

* Login com Google.
* Salvar tokens.
* Fazer refresh.
* Fazer logout.
* Limpar sessão.

---

### AuthInterceptor

Responsável por:

* Adicionar `Authorization: Bearer <accessToken>`.
* Em erro `401`, tentar refresh uma vez.
* Se refresh falhar, limpar sessão e redirecionar para `/login`.
